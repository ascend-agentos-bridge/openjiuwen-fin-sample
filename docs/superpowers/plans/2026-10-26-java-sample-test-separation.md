# Java 样例入口与测试分离

用户要求：main 简单、易读，展示正常生产使用；验收代码放测试，不能写在 main 中。

范围：本聊天已实现的样例 20–22。工作区另有并行开发中的 sample23，保持其文件与改动不动。20/21 由独立任务处理；22 和根回归/文档由主任务处理。

- [x] 20 移除 main 内嵌套顺序、工具边、模型次数、报告回传断言，迁移 JUnit；只保留业务装配、调用、结果和资源释放。
- [x] 21 移除验收缓存、verifyTrace、日志回读、VALIDATION/SUCCESS；保留完整日志数据，格式及真实调用验收迁移 JUnit。
- [x] 22 生产路径使用官方 BatchSpanProcessor + OTLP exporter，移除 InMemorySpanExporter、span 数量/结果断言、手动验收上传；内存 exporter 依赖改 test scope，收包与协议验收移 src/test。
- [x] main.py 只启动业务示例；各 sample 的 test.py 编排测试。根 run_all_samples.py 优先 test.py，未提供测试入口的旧样例仍运行 main.py。
- [x] 单元测试离线执行；涉及模型的集成验收继续调用真实 LM Studio，不使用 mock LLM。20、21、22 的模型验收串行执行，避免共享服务干扰。
- [x] README 明确示例/单元/真实模型集成测试命令，刷新受影响实测输出和根索引描述；检查源码/生产 classpath 不再混入验收依赖。

行为约定：遥测 SDK 按生产通常方式异步批量发送并在关闭时 flush；上传失败由 SDK 记录，不再因验收策略强制业务失败。测试分别断言业务结果与导出成败。日志与所有新实测输出必须来自真实运行。仅直接使用官方 API，不新增框架核心封装。

验证完成（2026-10-27）：20 的 5 个单元测试与 1 个真实模型集成测试通过；21 的 13 个单元测试与 2 个集成测试通过；22 的 4 个单元测试与 2 个真实模型/OTLP 集成测试通过，共 27 个测试。错误结果处理新增回归先失败后通过；普通业务答案无需验收标记。20–22 的 README 与版本化实测数据均已刷新，独立复核通过。未修改框架。
